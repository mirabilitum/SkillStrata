## 2. 术语表（锁定口径，防止再漂移）

| 术语 | 含义 | 不是什么 |
|---|---|---|
| **最小单元** | 一个自洽的可复用**目的**（如"文档→LLM友好md"） | ✗ 不是最小函数 / 最小格式处理器；pdf-to-md 不是单元 |
| **分支 branch** | 同一目的下的不同**输入路径**（pdf / docx / xlsx…） | ✗ 不是独立平级 skill |
| **就地迭代 iteration** | 对某分支的边缘处理/健壮性改进（如 `_repair_docx_relationships`） | ✗ 不是新工具，也不是重复 |
| **年轮** | 工具靠迭代累积的价值（格式扩展 / 健壮性伤疤 / 输出手艺） | ✗ 不是可归一化掉的杂质 |
| **共享后处理** | 跨分支通用、提到父级的处理（`table_to_list` / `sanitize_text`） | ✗ 不绑定单一分支 |
| **契约 contract** | 输入类型 + 输出类型 + 目的摘要；**合并的主轴 key** | ✗ 不是代码相似度 |
| **Composer** | 合并时**组织**变体（挂分支 + 提共享后处理） | ✗ 不是 Yunjue 的 Merger（重写成 canonical、删特化） |
| **三选一分类** | 新碎片 → 新工具 / 新分支 / 就地迭代\|重复 | ✗ 不是"重复 vs 新工具"二选一 |
| **价值确认** | 属性达标 + **持续被复用** | ✗ 不是"能跑通"或"diff 开源基线" |
| **确定性同质** | 单元内部不混确定性抽取与非确定性识别 | ✗ 混合即拆（识图是另一个单元） |

## 3. 设计骨架（一屏看全）

```
采集(每家薄adapter) → 统一trace(含 input/output_artifacts、determinism_signals)
  → Gate0 确定性探测 → Replay Gate → 属性 Output Gate
  → 契约抽取(观测I/O主锚) → 目的判同(Qdrant预筛 + LLM契约级裁决)
  → 三选一分类 → 入批次缓冲
  → Batch Evolution: Aggregator聚类 + Composer组织(保年轮)
  → 写库(branches + shared_post_processing + iteration_log + lineage)
  → 检索 + MCP暴露 + warm-start回灌(+ R_miss 安全阀)
```

主轴=契约/目的；副轴=代码相似(tree-sitter/ast-grep,只用于分支内"重复vs迭代"和薄壳识别)。

## 4. 已裁决的冲突（A–F，全部以 v0.4 口径为准）

来源主要是 `评估与记录框架`（Codex 最早写、早于 doc2md 顿悟）。裁决如下，升级该文档时照此执行：

| # | 冲突点 | 裁决 |
|---|---|---|
| **A** | `pdf-to-md` 当原子单元、与 `doc-to-md` 互为 merge_candidate | 改：最小单元=目的；pdf/docx 是 `doc-to-markdown` 的 **branch**，非平级 skill、非合并候选 |
| **B** | "原子性 Atomicity" 维度诱导拆小 | 重定义为 **"目的单一性"**：单目的=高分，跨目的长链=低分；目的内多分支不扣分 |
| **C** | 6 维主观打分 avg≥4 作为入库主门 | 主从确立：**四门(Replay/Output/Contract/Promotion)是客观主脊**；6 维打分降级为**路径B/边界情况的人审 rubric** |
| **D** | 上来给"通用性/稳定性"打分定价值 | 打分仅粗筛；**最终价值由持续复用确认**（年轮价值上来测不出） |
| **E** | 三套 manifest schema 并存 | 以 **v0.4 §9 / 对齐版 §7 的 schema 为准**（purpose+contract+branches+shared_post_processing+iteration_log+lineage）；把卡片里的 `aliases/trigger_conditions/not_for/examples` **折进 L1 元数据**，打分字段移到 review rubric |
| **F** | Obsidian 当承载层 | MVP 用 `distiller/` 文件树 + Qdrant + MCP；Obsidian 至多作**人看的视图层**（是否保留待用户拍板） |

**Gap（非冲突）**：`评估框架` 缺 Gate 0 / 确定性分级（早于 v0.3）→ 升级时补入，不矛盾。
